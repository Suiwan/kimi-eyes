## 正文（约 560 字，可直接发）

自部署的 DSH（DeepSeek Harness）+ DeepSeek 模型，原生都不支持识图。
发张截图过去，它只会回一句：当前模型不支持图片输入。

❓为什么
DSH 内置的读图工具要求「模型本身能看图」，DeepSeek 文本模型直接被拒。

💡思路
识图不一定要主模型亲自干。我有 Kimi 的 API（K3 视觉模型），给助手写了个小插件：
· 说一句「看看这张图」，助手自动调用 kimi_vision 工具
· 图片 base64 发给 Kimi K3，拿回文字描述
· 描述回到对话里，助手结合上下文继续推理

现在看图、读扫描件、分析图表都通了，还能追问「这个转化率为什么降了」——它会把图表里的数字和前面聊过的背景串起来回答。

🕳️ 踩坑（今晚真实经历，网上查不到）
1️⃣ 工具参数没走官方编译器，模型网关直接拒绝整轮请求，报错 'type: null'。翻了源码才发现：function schema 必须编译成 object 根 JSON Schema。
2️⃣ 改完代码死活不生效——loader 只在插件行名变化时才重新加载，ESM 还按 URL 缓存。最后用「行名带 ?v=N 版本号」实现不改配置不重启的热更新。
